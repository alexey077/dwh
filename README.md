## Полная проверка одной командой

Нужны Git, запущенный Docker Desktop / Docker Engine с Compose и Python 3 с venv. Проверенная версия Python в CI — 3.12. На macOS команды выполняются в Terminal или терминале VS Code.

```bash
git clone --branch hw1 https://github.com/alexey077/dwh.git dwh-final
cd dwh-final
./scripts/verify.sh --full
```

Скрипт поднимает стенд, применяет миграции, проверяет конкурентные операции, загружает полный объём, повторяет генератор и дельты, запускает оригинальный чекер, выполняет Э1–Э7 и повторяет чекер после отказов. Python-зависимости для экспериментов устанавливаются в .venv. На выходе сохраняются reports/check_report.json и reports/check_after_failures.json.

В CI полный запуск со сборкой занял около 12 минут; локальный первый запуск может быть дольше. Успешное завершение дважды печатает `All 139 official checks passed; automatic score 21/21`. Скрипт возвращает ненулевой код при любой неуспешной проверке.

Для проверки всех автоматических критериев без повторного проведения Э1–Э7: ./scripts/verify.sh. Каждая проверка добавляет новые тестовые дельты; повтор исходной порции seed 42 ничего не меняет. Конкурентные тесты используют временные базы и удаляют только их. Во время Э2–Э6 происходят намеренные отказы; после них скрипт восстанавливает узлы и режим репликации.

Если старый стенд запускался из другой папки, перед verify пересоздать контейнеры с текущими bind-mount. Именованные тома сохраняются:

```bash
docker compose up -d --build --force-recreate
```

## Минимальные команды из условия

Нужны Docker Engine с Compose v2 и Bash. Команды выполняются из корня репозитория. Python для миграций, генератора и чекера уже включён в образ.

```bash
docker compose up -d --build
./scripts/wait_ready.sh
./scripts/seed.sh --seed 42
./scripts/check.sh --verbose
```

Инициализация создаёт четыре базы, роли и структуру; повторный запуск проверяет контрольные суммы применённых миграций. Ожидание готовности проверяет роли узлов, доступность контрактов через пул и реплику. После генерации ожидается применение WAL обеими репликами.

Официальный чекер сохранён в `hw01/` без изменений. Обёртка сохраняет исходный результат в `reports/check_report.json` и возвращает его код завершения. Она переводит адреса из [манифеста](hw01_submission.yaml) во внутренние адреса Compose. При установленном на хосте Python можно запустить оригинал напрямую:

```bash
python -m pip install -r requirements.txt
python hw01/hw01_check.py --submission ./hw01_submission.yaml --json reports/check_direct.json --verbose
```

Первичная порция содержит 24 000 документов. Повтор тех же параметров не меняет данные. Для фиксированной дополнительной порции и её безопасного повтора:

```bash
./scripts/seed.sh --seed 777 --receipts 500 --batch-id DELTA-MANUAL
```

Чтобы каждый запуск создавал новую порцию, используется `--next-batch`. Именно так настроена команда `seed_delta` в манифесте. Опорный месяц выбирается при первой загрузке и сохраняется; для воспроизведения на пустом стенде его можно задать явно, например `--reference-month 2026-10-01`. Бизнес-значения воспроизводимы при одинаковых параметрах, технические timestamps отражают фактическую загрузку.

`docker compose down` останавливает стенд с сохранением данных. `docker compose down -v` удаляет его тома и используется только для полного сброса.

## Данные и допущения

Базовая загрузка даёт 2 400 клиентов, 2 100 карт, 600 SKU, 2 016 версий цен, 36 аптек, 3 600 партий и 7 200 строк закупок. История охватывает год и опорный месяц. Отдельная идемпотентная порция REVERSE-FLOWS-V1 добавляет три партии, три закупки и сценарии возврата поставщику, брака и просрочки. Причина и поставщик хранятся в wms.writeoff_detail; фиксированный contract сохраняет исходящий тип writeoff. Остатки вычисляются триггером из движений; продажи и возвраты имеют соответствующие складские операции.

Выходные выбираются с весом 2, первые 10% SKU — с весом 18, первые шесть аптек — с весом 5. Вероятность покупки без карты — 45%, доля возвратов — 3%; около 20% продаж имеют разделённую оплату. Измеренные результаты и окончательные объёмы после дельт приведены в отчёте SQL.

Цена выбирается в порядке аптека → регион → сеть. POS использует локальные версии SKU, цены и партии, затем сохраняет snapshots. Одна передача одной партии считается отдельным заказом перемещения; SLA доставки — 12 часов. Срок закупки хранится в `expected_at`. При обезличивании CRM очищает персональные данные и историю; будущий DWH должен применять события удаления, даже если BK клиента сохранился в старой продаже.
