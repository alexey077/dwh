# Расхождение в проверке Patroni

В исходном `hw01/hw01_check.py`, функция `check_ha`, здоровые узлы считаются выражением:

```python
running = [m for m in members if m.get("state") == "running"]
```

Затем требуется `len(running) == len(members)`. В документации Patroni 4.1.5 ответ `/cluster` содержит `state=running` у лидера и `state=streaming` у работающей реплики. Поэтому штатный кластер из трёх узлов может не пройти проверку `ha.running`.

Источники:

- [Оригинальный чекер курса](https://github.com/mgcrp/hse_ftda_dwh_course_2026/blob/e97e7476cf9f5e456e950967d53afc48145d1f21/hw01/hw01_check.py).
- [Patroni 4.1.5: Cluster status endpoints](https://patroni.readthedocs.io/en/latest/rest_api.html#cluster-status-endpoints).

Расхождение теперь воспроизведено на реальном Docker-стенде. В переданном `check_after_failures.json` успешная проверка `ha.members` содержит `pg1:replica/streaming; pg2:replica/streaming; pg3:leader/running`, а `ha.running` завершается с `running 1 из 3`. Все остальные 138 проверок успешны. Секции `repl` и маршруты HAProxy также успешны.

Исходный отчёт начислил **0/2 за HA** и **19/21 автоматических баллов**. Четыре ручных балла в нём ещё не выставлены. Если преподаватель признает расхождение и засчитает работающий HA, возможны ещё 2 балла, но такое решение не принято и в исходном результате не отражено. Подробный отчёт и SHA256 исходного JSON находятся в `docs/runtime_verification.md`.

20.10.2026 дополнительно проверен актуальный `master` курса: SHA файла чекера остаётся `af025ef41359f726082af8f4418f8207964571d0`, строгое сравнение с `running` присутствует. Это не исправленная версия официального чекера.

Чекер в `hw01/` сохранён без изменений. Скрипт `scripts/check.sh` возвращает его настоящий код завершения и сохраняет исходный JSON-отчёт. Ответ Patroni не преобразуется. `scripts/wait_ready.py` допускает оба документированных здоровых состояния, но это не меняет начисление баллов официальным чекером.

В подготовленном CI `tests/assert_runtime_report.py` требует все десять секций исходного отчёта. Он допускает только единственное расхождение `ha.running`, если живой API подтверждает ровно три ожидаемых здоровых узла, одного лидера и состояние `streaming` у реплики. В таком случае выдаётся предупреждение; исходный отрицательный результат и оценка сохраняются. Любая другая ошибка останавливает CI. Это проверка пригодности стенда для дальнейших экспериментов, а не исправление официальной оценки.

Для исправления в проверяющей программе следует считать здоровыми `running` и `streaming`, сохранив отдельные проверки единственного лидера и настоящей физической репликации. Решение о корректировке оценивания принимает преподаватель.
