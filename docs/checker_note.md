# Совместимость статуса HA с исходным чекером

В исходном отчёте на штатном /cluster Patroni 4.1.5 было 138/139 проверок и 19/21 автоматических баллов: healthy replica отображается как streaming, а чекер требует running.

Для текущего решения добавлен read-only сервис cluster-status, http://localhost:8011. Его /cluster объединяет реальные данные штатных /patroni каждого узла: state — состояние процесса PostgreSQL, replication_state — состояние WAL receiver. Исходный ответ /cluster доступен по /native/cluster; исходные /patroni остаются на портах 8008–8010. Роли и идентификаторы кластера сверяются, недоступность любого узла или остановка streaming возвращает HTTP 503.

Это дополнительный интерфейс мониторинга, объявленный в манифесте. Он не меняет ответы самих Patroni и не подменяет их константами. Исходный чекер не изменён. Разрешение пропускать ha.running из CI удалено: теперь требуются все проверки и 21/21 автоматических баллов. [Финальный CI](https://github.com/alexey077/dwh/actions/runs/39422163373) завершился успешно: 139/139 и 21/21 до и после Э1–Э7, без исключений. [Исходные доказательства](runtime_verification.md).

Обоснование формата: [ответ разработчика Patroni](https://github.com/patroni/patroni/discussions/3342) и [официальная документация REST API](https://patroni.readthedocs.io/en/latest/rest_api.html). Выбор и ограничения описаны в ADR 007.
