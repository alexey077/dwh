# 6. Повторяемые порции генератора

## Задача

Четыре независимые базы не дают общей транзакции для всей генерации. После сбоя нельзя повторно списать склад или получить дубликаты документов.

## Решение

Выбрал журнал порций `core.seed_run` в каждой базе. Справочники загружаются один раз. Порция документов получает стабильный идентификатор, seed, месяц истории и SHA-256 своего плана. Сначала фиксируется WMS, затем POS. Повтор завершённой порции ничего не пишет; после сбоя завершённый сервис пропускается, незавершённый повторяется.

## Почему не другой вариант

Вариант «при каждом запуске очистить все таблицы» отверг: он не поддерживает дельту и уничтожает историю источника. Вставки с одним ON CONFLICT для всех строк отверг: так легко скрыть частично загруженную порцию и дважды изменить остаток.

Указанный `--batch-id` повторяем. Режим `--next-batch` намеренно выбирает новую порцию под блокировкой генератора — это команда дельты для чекера. Изменившийся план незавершённой порции отклоняется, чтобы склад и касса не получили разные документы.

## Последствия

между фиксацией WMS и POS есть короткое окно несогласованности. Команда завершается успешно только после обоих сервисов; после ошибки нужно повторить ту же порцию. Это не распределённая транзакция и не обещание атомарности между базами.
